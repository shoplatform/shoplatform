# 開店平台 · v0.8（接上資料庫・第二階段）

零抽成、年費制的電商開店 SaaS 平台。
（獨立專案，與金融工具無關。）

- **`index.html`**：正式版，資料存在 Supabase 資料庫，任何裝置看到的都是同一份資料。
- **`demo.html`**：離線示範版，資料只存在這個瀏覽器，不用網路也能玩。

## v0.8 新增：接上資料庫（第二階段）

第一階段先隱藏的功能，現在正式版全部打開、資料都存在資料庫。

- **顧客會員（Email＋密碼）**：前台註冊填 Email、姓名、手機、密碼 → 收確認信 → 點信裡的連結就回到網站、自動完成註冊。有「忘記密碼」（寄重設信）、會員中心可以改姓名／手機、變更密碼。
- **舊訂單自動接上，但只認 Email**：以前沒登入、用同一個 Email 下過的訂單，註冊並確認信箱後會自動接到會員底下。只填同一支手機不會接上別人的訂單（防止冒用）。
- **會員等級**：後台「行銷 → 會員等級」設定，存在資料庫。結帳金額一樣由伺服器算：商品小計 → 滿額活動 → 會員等級折扣 → 優惠碼 → 運費。
- **商品圖片存雲端**：上傳到 Supabase Storage（`product-images`），不再受瀏覽器 5MB 限制。只有這家店的管理者能上傳、刪除；刪掉圖片或刪掉商品時，雲端檔案也會一起刪。每張圖最大 2MB（上傳前會自動縮小，一般照片不會超過）。
- **進銷存**：庫存總覽、盤點調整、庫存異動紀錄、進貨單（含部分入庫、移動平均成本）、供應商，全部改存資料庫。庫存帳和每一筆異動對得起來。
- **Email 連結**：確認信、重設密碼信的連結會帶 `?next=shop`／`?next=admin`／`?next=reset`，回到網站時自動登入並跳到對的頁面；連結過期或在別的瀏覽器打開，會提示該怎麼做。

## 從 v0.7 升級（照順序做）

1. **Supabase → SQL Editor → New query**：把新的 `supabase/schema.sql` 整份貼上，按 Run。看到「完成：資料庫是 v0.8 版」就好了。**原本的資料都會保留**（可以重複執行）。
   如果又跳出「Potential issues detected」，一樣按「Run and enable RLS」。
2. **Supabase → Authentication → URL Configuration**：確認 Redirect URLs 裡有 `https://shoplatform.github.io/shoplatform/**`（v0.7 設過就不用動）。
3. **Supabase → Authentication → Sign In / Providers → Email**：「Confirm email」保持**打開**（舊訂單接上靠的就是信箱驗證）。
4. **GitHub**：用 Upload files 把 `index.html`、`demo.html`、`README.md`、`css`、`js`、`supabase` 六樣拖進去覆蓋，按 Commit changes，等 1～2 分鐘。

> **正式開放給顧客前要做：自訂寄信（SMTP）**。Supabase 內建的寄信服務只會寄給「專案成員」的信箱，而且每小時只能寄幾封，只適合自己測試。要讓一般顧客收得到確認信，要到 **Authentication → Emails → SMTP Settings** 接上寄信服務（例如 Resend、Brevo，有免費額度）。在那之前，可以先用你自己的 Email 測試會員註冊。

## 第一次設定（全新的 Supabase 專案才需要）

1. **Supabase → Authentication → URL Configuration**：Site URL 填 `https://shoplatform.github.io/shoplatform/`；Redirect URLs 加一筆 `https://shoplatform.github.io/shoplatform/**`。
2. **Supabase → SQL Editor → New query**：把 `supabase/schema.sql` 整份貼上，按 Run。看到「完成：資料庫是 v0.8 版」就完成。
3. **把檔案上傳到 GitHub**（見下方），等 1～2 分鐘。
4. **打開網站的商家後台**（網址後面加 `#admin`）→「第一次使用？建立帳號」→ 用你的 Email 註冊 → 到信箱點確認連結（會直接回到後台）。
5. 畫面會出現「還差一步：設定店主」，照畫面把那一行指令貼到 SQL Editor 執行，回來按「重新檢查」就進得去了。

連線設定在 `js/config.js`：Supabase 網址、Publishable key（公開金鑰，本來就放在網頁裡）、商店代號。**不要把 Secret key／service_role 放進任何檔案。**

## v0.7：接上 Supabase 資料庫（第一階段）

- **資料放雲端**：商品、分類、設定、訂單、顧客、優惠券、滿額活動都存在 Supabase。手機下的單，電腦後台馬上看得到。
- **商家後台要登入**：Email＋密碼。只有被設成「店主」的帳號能進後台；別人就算註冊了也看不到任何資料。
- **金額由伺服器算**：購物車、結帳的金額、滿額折、優惠碼都由資料庫計算；下單時重新檢查庫存、價格、優惠碼，瀏覽器送來的價格一律不採用。
- **不會超賣**：同時很多人搶最後幾件，只有庫存夠的訂單會成立（測過 8 人搶 3 件，剛好成立 3 張）。
- **改庫存不會蓋掉剛賣掉的**：商品頁改庫存時，只送「這次改了多少」，這段時間顧客買走的數量不會被覆蓋。
- **資料庫全部上鎖**：資料表不開放直接讀寫，只能透過 `supabase/schema.sql` 裡的函式；前台函式只回公開資訊（不含成本、商家備註、內部設定）。

## v0.6 新增（進銷存）

- **庫存**：後台「進銷存 → 庫存」。每個規格一列：可售庫存、在途（已下單還沒到貨）、平均成本、庫存成本；上方有規格數、庫存件數、庫存總成本、庫存偏低數。可以篩選偏低／缺貨、匯出 Excel。
- **盤點調整**：每一列按「調整」，可以填「盤點後的實際數量」或「增減數量」，要選原因（盤點差異、損壞報廢、樣品／贈品、找回、其他）。庫存不會被調成負數。
- **庫存異動紀錄**：每一次庫存變動都會記下來：銷售、訂單取消加回、進貨入庫、盤點調整、在商品頁直接改、期初庫存。每筆有時間、增減、變動後剩多少、對應的訂單或進貨單（點了可以跳過去）、備註。可以看全部或只看某個規格。
- **進貨單**：草稿 → 已下單 → 部分入庫 → 已入庫，也可以取消。可以一鍵「帶入庫存偏低的規格」（已經算進在途數量，不會重複補），系統建議補到提醒數量的 3 倍。貨到了按「入庫」，可以只收一部分；剩下的不收了就按「剩下的不收了」結案。
- **平均成本**：入庫時用移動平均自動更新：（原庫存 × 原成本 ＋ 入庫數量 × 這次進價）÷ 新庫存。商品編輯頁也多了「平均成本」欄；訂單會記下當時的成本，之後可以算毛利。
- **供應商**：名稱、聯絡人、電話、Email、統一編號、地址、備註；可以看他的進貨紀錄、直接「向他進貨」。還有未入庫進貨單的供應商不能刪除。
- **修正**：手機寬度下後台選單太長時，整頁會被撐寬、要左右滑；現在只有選單列本身可以橫向捲動。

## v0.5 新增

- **會員分級**（藍圖 B3-02）：後台「行銷 → 會員等級」。最多 5 個等級，每級設升級門檻、折數（95 = 95 折）、要不要免運。消費只算「已付款、沒取消」的訂單；可以選「全部累積（只升不降）」或「最近 12 個月（會自動降級）」。
- **結帳怎麼折**：商品小計 → 滿額活動 → 會員等級折扣 → 優惠碼 → 運費。等級優惠要會員登入後結帳才會套用；沒登入時購物車會提醒可以登入享優惠。
- **會員中心**：顯示目前等級、權益、升級進度條，和「再消費多少升級」；可以展開看全部等級。
- **後台會員**：列表多一欄等級、可以依等級篩選；會員頁顯示有效消費和升級進度。
- **範例等級**：一般會員（0）、銀卡（滿 3,000，95 折）、金卡（滿 10,000，9 折＋免運）。示範帳號 0912345678 目前是銀卡。

## v0.4 新增

- **優惠券**（藍圖 B4）：後台「行銷 → 優惠券」。三種優惠：折固定金額、打折（85 代表 85 折，可設最多折多少）、免運。每張可以設使用門檻、開始／結束日期、總共可用次數、每位顧客可用次數（用會員帳號或下單手機計算）、限會員使用、能不能和滿額活動一起用、啟用開關。訂單取消後，次數會自動退回。
- **滿額活動**（藍圖 B4）：後台「行銷 → 滿額活動」。可以設好幾段，例如「滿 1500 折 150、滿 3000 折 400」，結帳時自動套用最划算的一段（不疊加）；可設期間與開關。
- **前台**：最上方公告列會顯示進行中的活動；購物車和結帳可以輸入優惠碼，不能用時會直接說原因（還差多少、已過期、限會員、已經用過…）；會提示「再買多少可以多折／免運」；免運門檻看的是折扣後的金額。
- **訂單**：折扣明細會記在訂單上，後台訂單頁、顧客的訂單頁都看得到；匯出 Excel 多一欄「優惠碼」。
- **範例資料**：`WELCOME100`（滿 800 折 100，每人一次）、`AUTUMN85`（滿 1000 打 85 折，最多折 300，不能和滿額活動併用）、`FREESHIP`（會員免運，滿 500）、`SUMMER50`（已過期，示範用）、「秋季滿額折」滿 1500 折 150／滿 3000 折 400。

## v0.3 新增

- **前台會員註冊／登入**（藍圖 A2-01）：帳號是手機號碼。註冊要先拿手機驗證碼——簡訊還沒串接，所以目前是「示範模式」，驗證碼直接顯示在畫面上。密碼至少 8 碼、要有英文和數字，只存加鹽雜湊（SHA-256），不存原文；密碼連錯 5 次暫停 5 分鐘。以前用同一支手機結帳過的顧客，註冊後會自動接上原本的訂單。
- **會員中心**：我的訂單、修改姓名與 Email、變更密碼、登出。登入後結帳會自動帶入會員資料，訂單直接掛在會員帳號下。
- **訂單查詢**（藍圖 A2-02）：不用登入，輸入訂單編號＋下單手機就能看訂單進度（待付款 → 備貨中 → 已出貨 → 已完成）、物流單號、付款說明。顧客看不到商家備註；手機號碼會遮一部分。
- **顧客自行取消**：「待付款」的訂單顧客可以自己取消，庫存自動加回；已經在處理的訂單要聯絡客服。
- **下單完成頁**：可以直接「查看訂單」；還不是會員的話，提示「設定密碼成為會員」，按下去會帶入剛剛的手機和姓名。
- **後台會員頁**：顯示每位會員「已開通／未開通」帳號。
- **示範帳號**：手機 `0912345678`、密碼 `demo1234`（林雨潔）。

> 這一版也修掉一個問題：以前沒登入結帳時，會用 Email 去比對既有會員，打錯或借用別人的 Email 會讓訂單掛到別人名下。現在只用手機比對，而且不會覆蓋已開通會員自己維護的資料。

## v0.2 新增

- **商品圖片上傳**（藍圖 B1）：商品編輯頁可以點選或拖曳上傳，每個商品最多 8 張；第一張是主圖，可以「設主圖」、「移除」。圖片會在瀏覽器裡自動縮小（長邊 1200px）並轉成 JPEG，透明背景會變成白底。前台列表、商品頁（可切換多張圖）、購物車、後台列表都會顯示主圖；沒有圖片的商品照舊用色塊。
- **訂單匯出 Excel**（藍圖 B2-06）：訂單頁右上角「匯出 Excel」。依照目前的狀態分頁和搜尋條件匯出，可以再選「不限日期／本月／自訂日期」。下載的是真正的 `.xlsx`，有兩張工作表：「訂單」（一張訂單一列）與「訂單明細」（一個商品一列），標題列凍結、可篩選，金額有千分位，手機號碼開頭的 0 會保留。不需要任何外部套件。

> **圖片目前的限制**：圖片跟其他資料一起存在瀏覽器的 localStorage，大約只有 5MB，一般商品照片大概能放 20～30 張。空間不夠時會跳出提示、不會存到一半。等換成真正的後端（階段 2），圖片會改存雲端，這個限制就沒了——只需要改 `js/db.js` 裡的 `DB.media.prepare()`。

**商店前台**（`#shop`）
- 會員註冊／登入、會員中心、訂單查詢（v0.3）

## 怎麼在自己電腦上打開

- 正式版 `index.html` 需要網路，會連到 Supabase。
- 離線示範版：直接用瀏覽器打開 `demo.html` 就可以。
上方黑色的 **DEV** 列可以在「商家後台」和「商店前台」之間切換。

資料存在瀏覽器的 localStorage：換瀏覽器或清除網站資料就會回到範例資料。
後台「設定 → 重置範例資料」也可以手動還原。舊版留下的資料會自動升級，不用重置。

## 放上 GitHub（GitHub Pages 免費網址）

1. 在 GitHub 建一個新的 repository，例如 `shop-platform`（Public 或 Private 都可以；Pages 免費版需要 Public）
2. 把這個資料夾的檔案上傳：
   - 最簡單：在 repository 頁面按 **Add file → Upload files**，把整個資料夾內容拖進去，按 **Commit changes**
   - 或用指令（這個資料夾已經是 git 專案）：
     ```bash
     git remote add origin https://github.com/<你的帳號>/shop-platform.git
     git branch -M main
     git push -u origin main
     ```
3. 到 repository 的 **Settings → Pages**，Source 選 **Deploy from a branch**，Branch 選 `main`、資料夾選 `/ (root)`，按 Save
4. 等 1～2 分鐘，網址會是 `https://<你的帳號>.github.io/shop-platform/`

已經放過舊版的話：用 **Upload files** 把 `index.html`、`demo.html`、`README.md`、`css`、`js`、`supabase` 拖進去覆蓋即可。

## 設計原則

- **頁面只跟 `DB` 說話**：所有讀寫都經過 `window.DB`。資料庫版（`db.js`）和離線版（`db-local.js`）提供一樣的介面：讀取從快取同步拿，寫入是非同步、成功後重新載入。
- **多租戶從第一天就在**：資料結構是 `stores[商店ID]`，現在只有一家示範店，之後開放多商家時不用改資料形狀。
- **不用任何框架或打包工具**：純 HTML / CSS / JavaScript，任何人打開就看得懂，也方便用 AI 一段一段加功能。
