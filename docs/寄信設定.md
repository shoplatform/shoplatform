# 自訂寄信（SMTP）設定指南

這份指南用白話說明如何讓一般商家與顧客收到註冊確認信、忘記密碼信。建議使用 **Resend**；也可以換成任何支援 SMTP 的寄信服務。

> 重要：SMTP 密碼、Resend API key 都是祕密。只填在 Supabase 後台，絕對不要放進 GitHub、`js/config.js` 或任何專案檔案。

## 為什麼一定要設定

Supabase 內建寄信只供測試：通常只能寄給專案團隊成員，而且限制很低，不適合正式開放。設定自訂 SMTP 後才能寄給一般使用者。

官方說明：

- [Supabase：設定自訂 SMTP](https://supabase.com/docs/guides/auth/auth-smtp)
- [Resend：搭配 Supabase](https://resend.com/supabase)

## 一、準備寄件網域

建議先有自己的網域，例如 `yourdomain.com`，並使用：

- 寄件名稱：你的平台名稱
- 寄件信箱：`no-reply@auth.yourdomain.com`
- 驗證信專用子網域：`auth.yourdomain.com`

在 Resend 新增寄件網域後，依畫面到網域 DNS 後台新增它提供的 SPF、DKIM 等紀錄。等 Resend 顯示網域已驗證，再進行下一步。

若還沒有自己的網域，先不要正式開放外部註冊；可以繼續使用 Supabase 內建寄信測試專案團隊成員。

## 二、建立 Resend SMTP 密碼

1. 登入 Resend。
2. 建立一組只給 Supabase 使用的 API key。
3. 複製後先放在密碼管理器；離開畫面後通常不能再看完整內容。
4. 不要把這組 key 貼進任何程式碼或 GitHub。

## 三、填入 Supabase

進入 Supabase 專案，找到 **Authentication → Email／SMTP 設定**，開啟自訂 SMTP，填入：

| 欄位 | Resend 設定 |
|---|---|
| Sender email／寄件信箱 | `no-reply@auth.yourdomain.com` |
| Sender name／寄件名稱 | 你的平台名稱 |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | 上一步建立的 Resend API key |

儲存後，Supabase 自訂 SMTP 預設仍有每小時 30 封的限制。需要提高時，到 **Authentication → Rate Limits** 調整；剛開始不要一次拉得太高，以免被機器人濫用。

## 四、貼上中文信件範本

進入 **Authentication → Email Templates**：

### Confirm signup／確認註冊

- Subject：`請確認你的 Email｜你的平台名稱`
- Body：複製 [`docs/email-templates/確認註冊.html`](email-templates/確認註冊.html) 的全部內容

### Reset password／重設密碼

- Subject：`重設密碼｜你的平台名稱`
- Body：複製 [`docs/email-templates/重設密碼.html`](email-templates/重設密碼.html) 的全部內容

請把範本裡的「你的平台名稱」換成正式名稱。不要改掉 `{{ .ConfirmationURL }}`，它會由 Supabase 自動換成一次性安全連結。

## 五、確認網址設定

到 **Authentication → URL Configuration** 確認：

- Site URL：`https://shoplatform.github.io/shoplatform/`
- Redirect URLs 內含：`https://shoplatform.github.io/shoplatform/**`

本專案會依註冊位置帶回商家後台或商店會員頁；缺少 Redirect URL 時，使用者可能會被帶到錯誤網址。

## 六、正式驗收

請使用一個「不是 Supabase 專案成員」的新 Email，依序測試：

- 商家註冊：收到中文確認信，點擊後回到商家後台。
- 顧客註冊：從示範商店註冊，收到中文確認信，點擊後回到商店並完成會員資料。
- 忘記密碼：收到中文重設信，點擊後能設定新密碼，再用新密碼登入。
- 錯誤連結：重複點已用過或過期連結，網站會顯示可理解的提示。
- 查看 Resend Logs：三封信都顯示已送達；若失敗，先看錯誤原因與 suppression list。
- 查看垃圾信件匣：確認寄件名稱、寄件網域正常，沒有使用未驗證的寄件地址。

全部通過後，才算完成「外部使用者可以註冊」。

## 常見問題

### 完全收不到信

先看 Supabase Authentication Logs，再看 Resend Logs。Supabase 顯示已交給 SMTP 後，後續送達問題要從 Resend 的紀錄檢查。

### 顯示寄件者未驗證

Sender email 必須使用 Resend 已驗證的網域，不能任意填 Gmail 或其他未驗證地址。

### 一直被限制寄信

先確認不是程式或機器人重複觸發，再到 Supabase Rate Limits 調整。正式大量開放前，建議加 CAPTCHA 防護。

### 信件容易進垃圾信件匣

確認 SPF、DKIM、DMARC 設定；驗證信只放必要文字與一個按鈕，不要加入促銷內容或太多圖片。
