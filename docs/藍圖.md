## 1. 專案是什麼

- **產品**：台灣的電商開店 SaaS 平台（含進銷存）。商家付**固定年費**、平台**不抽成**。
- **角色**：
  - **平台方**：專案擁有者本人，管理所有商家、收年費。
  - **商家**：來開店的人（店主），可以邀請員工一起管店。
  - **顧客**：到各家店買東西的人，可以註冊成那家店的會員。
- **開發順序**：先蓋骨架（P0）→ 再長肉（P1）→ 最後做外觀跟差異化（P2）。
- **目前技術**：純 HTML／CSS／JavaScript（沒有框架），放在 GitHub Pages；資料庫、登入、圖片存在 Supabase（免費方案，東京機房）。
- **獨立專案**：跟擁有者的其他工作完全無關，不要出現任何金融品牌名稱。
- **暫不處理**：金流、物流、電子發票（付款、出貨、退款都由商家在後台手動確認與記錄）。

### 安全與防護
- 資料表全部開 RLS 並撤銷直接存取，只能透過函式；後台函式都檢查權限（店主／員工權限）；沒權限的員工看不到成本
- 金額、折扣、庫存都在伺服器計算；下單鎖庫存（測過 8 人搶 3 件剛好成立 3 張）
- 防灌單：同一支手機 10 分鐘 5 筆、一天 20 筆、未付款最多 5 筆；同 IP 10 分鐘 20 筆；整店每小時 300 筆；結帳隱藏欄位擋機器人
- 防猜訂單：查單打錯只回「查不到」；每筆 10 分鐘 10 次、每個 IP 30 次

### 資料流
1. `app.js` 依網址決定「side」：home／shop／admin／platform。
2. 進頁面前呼叫 `DB.ready(side)`：Supabase 版會載入那一側的資料到快取（前台：`shop_catalog`；後台：`admin_bootstrap`）。
3. 頁面同步讀 `DB.xxx.list()/get()`；寫入呼叫 `await DB.xxx.save()`，完成後重新載入快取。
4. 所有寫入都是呼叫 `schema.sql` 裡的函式，函式檢查身分與權限。

### 資料表
`stores`（商店、設定 JSON、方案）、`store_members`（店主／員工與權限）、`store_invites`（員工邀請）、`categories`、`products`、`variants`、`customers`、`orders`、`order_refunds`、`coupons`、`promotions`、`stock_movements`、`suppliers`、`purchases`、`reviews`、`platform_admins`、`platform_settings`、`platform_billing_log`、`rate_events`

### 主要函式
- 前台：`shop_catalog`、`shop_quote`、`shop_place_order`、`shop_order_lookup`、`shop_cancel_order`、`shop_member_*`、`shop_my_orders`、`shop_reviews`、`shop_my_reviewables`、`shop_review_save`
- 後台：`admin_bootstrap`、`admin_search_orders`、`admin_get_order`、`admin_set_order_status`、`admin_bulk_set_status`、`admin_refund_order`、`admin_save_product`、`admin_save_products_bulk`、`admin_sort_products`、`admin_duplicate_product`、`admin_report`、`admin_staff_*`／`admin_invite_*`、`admin_reviews`…
- 平台：`platform_overview`、`platform_record_payment`、`platform_set_until`、`platform_set_plan`、`platform_set_suspended`、`platform_save_settings`、`platform_public`
- 設定（只能在 SQL Editor）：`setup_add_owner(代號, email)`、`setup_platform_admin(email)`、`setup_demo_store()`

### 權限
店主全部都可以；員工依勾選：`orders` 訂單、`customers` 會員、`products` 商品（含評價）、`inventory` 進銷存、`marketing` 行銷、`reports` 報表、`settings` 設定與外觀。有 `inventory` 或 `reports` 才看得到成本。

## 4. 部署（擁有者自己操作的方式）

1. **資料庫**：Supabase → SQL Editor → New query → 貼上整份 `supabase/schema.sql` → Run → 看到「完成：資料庫是 vX.Y 版」。可以重複執行，資料會保留。如果出現「Potential issues detected」，按「Run and enable RLS」。
2. **網站**：GitHub repository → Add file → Upload files → 把 `index.html`、`demo.html`、`README.md`、`css`、`js`、`supabase`（以及 `AGENTS.md`、`docs`、`test`）拖進去 → Commit changes → 等 1～2 分鐘。
3. **第一次設定**（已完成）：Supabase Authentication → URL Configuration 的 Site URL 與 Redirect URLs（`https://shoplatform.github.io/shoplatform/**`）；`select setup_platform_admin('擁有者email');`。

## 5. 已知限制

- 金流、物流、電子發票都沒有串接；年費由平台手動登記。
- 顧客與商家的確認信目前用 Supabase 內建寄信：**只會寄給專案成員、而且每小時很少封**。開放給外人註冊前一定要接自訂 SMTP。
- GitHub Pages 是靜態網站：每個商品沒有獨立的分享預覽（Facebook／LINE 分享看不到商品圖）、不能幫每家店接自己的網域。
- 會員列表、庫存異動紀錄一次載入（量很大時要改分頁）。
- Supabase 免費方案沒有自動備份到任意時間點；要定期匯出。
- 商家不能自己刪除商店；平台管理者不能直接進別人的後台（刻意的）。
- 評價只開放給會員。
