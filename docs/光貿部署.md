# v0.60 光貿電子發票部署與驗收

本版提供「可部署的測試串接」，不是上傳 GitHub 後就自動正式開票。
離線示範版只模擬，不連光貿。正式網站呼叫 Supabase Edge Function，金鑰以 AES-GCM 加密保存在獨立資料表，前台和平台備份不回傳密鑰。

## 1. SQL

已有 v0.59 資料庫：只執行 `supabase/invoice-v060.sql`，不必重跑完整 schema。
新建專案：執行完整 `supabase/schema.sql`（已含同一份增量）。
舊有 v0.59 的下單函式需一起更新，增量也會包含必要的新版下單函式。
執行後看到：`完成：光貿電子發票 v0.60 已安裝（需另外部署 Edge Function）`。
務必使用開店平台自己的 Supabase 專案，不要執行到其他系統。

## 2. Edge Function

部署 `supabase/functions/amego-invoice/index.ts` 與同目錄 `core.mjs`。
CLI（在專案根目錄）：

```sh
supabase functions deploy amego-invoice --project-ref <開店平台專案代號> --no-verify-jwt
```

JWT 在函式內由 `auth.getUser()` 驗證，並以呼叫者權限檢查商店。`--no-verify-jwt` 是讓排程與新的 Publishable Key 可到達函式；不是省略身分與店家權限驗證。

Supabase Secrets 設定：

- `INVOICE_MASTER_KEY`：32 隨機 bytes 的 Base64，首次建立後安全備份。可在本機使用 `openssl rand -base64 32` 產生；不要放 GitHub、截圖或聊天中。
- `INVOICE_CRON_TOKEN`：另外產生的長隨機字串，只供排程使用。
- `AMEGO_LIVE_ENABLED`：先保持 `false`，測試及正式驗收完成前不要開啟。
- `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、`SUPABASE_ANON_KEY`：使用 Edge Function 環境內建值；若平台改用新式金鑰，確認後端 SDK 的憑證有效。

正式金鑰由店主在商家後台輸入，僅經 HTTPS 傳到 Edge Function；不寫入 `config.js`，也不回傳給瀏覽器。主金鑰不能任意更換，否則原憑證無法解密。

## 3. 背景工作

排程每分鐘以 POST 呼叫：
`https://<專案代號>.supabase.co/functions/v1/amego-invoice`

Header：`Authorization: Bearer <INVOICE_CRON_TOKEN>`、`Content-Type: application/json`
Body：`{"action":"run"}`

可用 Supabase Cron 搭配 Vault 保存排程密鑰。尚未設定排程時，POS 結帳仍會嘗試開票，商城單筆收款確認也會嘗試；批次收款與背景補查需由發票列表操作或設定排程。
每次最多處理 20 家有待處理工作的商店，各 1 筆，依最久未處理時間排序；大量商家正式開放前需再調整處理量與監控。

## 4. 商家啟用

後台 → 電子發票 → 光貿設定 → 選測試環境 → 測試連線 → 勾選啟用／自動開立 → 驗證並儲存。
測試使用光貿官方公開測試統編／App Key；測試交易內容不要填真實顧客個資。
測試連線呼叫發票列表 API，只驗證憑證，不開發票，也不代表字軌、發票機和正式稅務申請已完成。

## 5. 必要驗收

1. 現金 POS 結帳後只扣一次庫存、只建一筆訂單與一個發票工作。
2. 載具、公司統編、Email 會員載具、捐贈各測一筆。
3. 網路轉帳訂單先保持未付款，確認收款後才有開票工作；取貨付款直到實際收款確認才開票。
4. 關閉自動開立：建立待手動開立紀錄，不自動送出。
5. 外部服務逾時：交易仍成立，重試只查原訂單，不再次收款／扣庫存／直接重開票。
6. 非店主不可改憑證；其他店家不能讀或操作本店設定與發票。
7. 確認開票號碼在光貿測試後台存在，財政部上傳狀態不能只以 API 受理成功判定。

## 6. 本階段範圍

全筆 5% 應稅、含稅價格；B2C 不拆稅，打統編時拆稅，依光貿官方規格。
POS 與商城共用發票記錄，POS 支援 SKU 掃描槍（需輸入既有 SKU 後送 Enter），尚未增加獨立商品條碼欄位。
現場可選擇「需要寄送」，收件資料與運費保存在正式訂單，列入待出貨；物流 API 尚未串接，寄件與單號仍由商家人工處理。
收據是交易明細，不是紙本發票證明聯。未接印表機前使用載具／捐贈／Email 電子通知。
作廢、退款折讓、補寄通知、修改買受人及紙本發票機在本階段由光貿後台處理，不會宣稱退款後發票已自動作廢。後續另做完整售後串接。
若光貿拒絕或回覆不明，請到光貿核對原交易，系統採保守查詢，不會自動建立另一個開票識別碼。
正式開放前需一間已獲光貿開通的商家，以自己的統編及 App Key 完成驗收，再將 `AMEGO_LIVE_ENABLED` 設為 `true`。

官方 API 文件：https://invoice.amego.tw/api_doc/
官方範例：https://invoice.amego.tw/api_doc/example
